## 3. 受け入れ基準 (Acceptance Criteria)

> **書き方:** 「[前提条件] のとき、[操作] すると、[期待結果] になること」の形式で書く。
> テスト担当者がそのままテストケースに変換できる粒度にすること。
>
> **必ず以下の4カテゴリをすべて記述すること:**
> - `[正常系]` ハッピーパス
> - `[エラー系]` バリデーション失敗・システムエラー
> - `[境界値]` 最大・最小・空・NULL
> - `[権限]` 権限なし・未認証

### 正常系

- [ ] AC-001 `[正常系]` [前提条件] のとき、[操作] すると、[期待結果] になること
- [ ] AC-002 `[正常系]` ...

### エラー系

- [ ] AC-010 `[エラー系]` [エラー条件] のとき、[エラーメッセージ・挙動] が表示されること
- [ ] AC-011 `[エラー系]` 外部システムとの通信がタイムアウトしたとき、ユーザーに[メッセージ]を表示し、操作を中断しないこと

### 境界値

- [ ] AC-020 `[境界値]` [項目] が最大値ちょうどのとき、正常に処理されること
- [ ] AC-021 `[境界値]` [項目] が最大値+1のとき、エラーになること
- [ ] AC-022 `[境界値]` [項目] が空・NULL のとき、[期待する挙動] になること

### 権限

- [ ] AC-030 `[権限]` 未認証ユーザーがアクセスしたとき、ログイン画面にリダイレクトされること
- [ ] AC-031 `[権限]` 権限のないロールがアクセスしたとき、403エラーが返ること
- [ ] AC-032 `[権限]` 他ユーザーのデータを操作しようとしたとき、[期待する挙動] になること

# エンタープライズ観点チェックリスト (Enterprise Checklist)

> このドキュメントの目的は「検討した証跡を残すこと」である。
> 適用しない項目も **✗（対象外）と理由を必ず記入する**。
> 「見ていない」と「見て除外した」を区別することがこのリストの価値。
>
> **記入ルール:**
> - `○` 適用する → `対応方針 / 参照先` に具体的な内容を記入
> - `✗` 対象外 → `対象外の理由` を必ず記入
> - `-` 未検討 → **README.md のタスク一覧に `CL` 種別で登録し**、リリース前に ○ / ✗ に解決すること
>
> **このチェックリスト完了後の必須作業:**
> - このドキュメントは **全アプリケーション種別に共通** のベースライン項目です
> - このチェックリスト完了後、**必ず `application_checklist.md` の該当セクションも記入してください**
>   - Web アプリケーション → Section 1
>   - ローカル GUI アプリケーション → Section 2
>   - ローカル CUI / CLI アプリケーション → Section 3

## 記入方針（本プロジェクトでの適用判断）

本システムは **単一利用者の個人ツール**であり、CLI として GitHub Actions 上で週1回
無人実行されるバッチである（要件定義 §1）。この性質から、以下の観点群は
構造的に適用対象を持たないため `✗` としている。「検討していない」のではなく
「検討した上で対象がないと判断した」ものである。

| 観点群 | ✗ とした根拠 |
|---|---|
| 認証・パスワード関連 (S-A01〜S-A08) | システム内部に認証機構を持たない。実行環境側のアクセス制御に委ねる (REQ-NF-005) |
| Web 由来の攻撃対策 (S-I02, S-I03, S-D06) | ブラウザへ応答を返す経路を持たない |
| 受信側のレート制限・DoS (S-R01〜S-R03) | 外部から到達可能なエンドポイントを公開しない。本システムは常に呼び出す側 |
| 冗長化・DR (R-H01〜R-H05, O-D01〜O-D04) | RTO を1週間（次回実行での自動回復）と定義しており、冗長構成を要しない (REQ-NF-003) |
| データプライバシー (C-P02〜C-P06) | 公開記事のメタデータのみを扱い、個人データを保持しない |
| 体制・ガバナンス (C-G01, C-G02, O-I03, O-I05, O-C01) | 単一利用者であり、権限境界・報告先・承認者が存在しない |

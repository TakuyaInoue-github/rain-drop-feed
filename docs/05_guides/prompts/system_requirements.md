主要な機能の概要:
- [機能1の概要]
- [機能2の概要]

性能目標の根拠:
[例: 現在のアクティブユーザー数500人、ピーク時アクセス1,000 req/min、

連携する外部システム:
- [外部システム1]: [連携内容・障害時の許容範囲]

## 出力指示

- 機能要件は「[ロール]は、[状態・条件]のとき、〜できること」の形式を守ること
- 権限マトリクスをロール × 操作のテーブルで網羅すること
- 非機能要件の数値には必ず根拠を記載すること
- 外部システム連携テーブルの「障害時の挙動」「代替手段」を省略しないこと
- enterprise_checklist.md と application_checklist.md のどの項目が
  `-`（未検討）になるかを末尾にリストアップし、README.md タスク登録を促すこと
```

## レビュー・抜け漏れチェック

```
docs/SKILL.md を読んでから、
docs/01_requirements/system_requirements.md をレビューしてください。

以下の観点で確認し、「問題あり / 要確認 / 問題なし」で報告してください:

1. 各機能要件に「誰が・どの状態で・どの権限で」が明記されているか
   （「システムは〜できること」のような主語なし記述になっていないか）
2. 権限マトリクスに未定義の操作がないか
3. 非機能要件の数値に根拠が記載されているか
4. 外部システム連携に「障害時の挙動」が定義されているか
5. データ保持期間と廃棄方法が記述されているか
6. enterprise_checklist.md / application_checklist.md の `-` 項目が
   README.md のタスク一覧に登録されているか
7. トレーサビリティマトリクスが埋まっているか

問題がある箇所は具体的な修正案を示すこと。
```

## 非機能要件の数値根拠レビュー

> 「なんとなくで書いた数値」を洗い出したいとき。

```

docs/01_requirements/system_requirements.md の非機能要件セクションを確認してください。

各数値目標について:
1. 根拠が記載されているか
2. 根拠が「業務要件・ユーザー調査・既存システムの実績」のいずれかに基づいているか
3. 根拠のない数値（「なんとなく2秒」等）を特定し、根拠として考えられる情報を提示すること

根拠が不明な数値は OQ として README.md への登録を促すこと。

# プロンプト: 要求定義 (business_requirements.md)

> 対象ファイル: `docs/01_requirements/business_requirements.md`

---

## 初稿生成

```
docs/SKILL.md を読んでから、
docs/01_requirements/business_requirements.md の初稿を生成してください。

## コンテキスト

プロジェクト名: [プロジェクト名]
一行サマリー: [このシステムが何を解決するか1文で]

ステークホルダー:
- [ロール1]: [関心事]
- [ロール2]: [関心事]

困っているのは誰か:
[例: 営業担当者が月次レポートを集計するとき]

トリガー（何をしようとしたときに困るか）:
[例: 複数システムからデータをエクスポートして手動でExcelに貼り付けるとき]

現状の症状（観察できる事実・数値）:
[例: 月次集計に1人約8時間かかっている。転記ミスが月3〜5件発生している]

根本原因（なぜ症状が起きているか）:
[例: データが複数システムに分散しており一元参照手段がない]

解決後の姿（To-Be）:
[例: 自動集計で30分以内に完了する。転記ミスがゼロになる]

スコープに含めないもの:
[例: モバイルアプリ対応、既存データの移行]

制約（期限・予算・法規制等）:
[例: リリース期限 YYYY-MM-DD]

## 出力指示

- 症状と根本原因を区別して記述すること
- 成功基準は定量値・測定方法・計測タイミングをセットで書くこと
- 各 R-xxx に優先度（Must/Should/May）と根拠を付けること
- Out of Scope は「対象外にする理由」とセットで書くこと
- 不明点は OQ として末尾に列挙し、README.md への登録対象であることを示すこと
```

## レビュー・抜け漏れチェック

```
docs/SKILL.md を読んでから、
docs/01_requirements/business_requirements.md をレビューしてください。

以下の観点で確認し、「問題あり / 要確認 / 問題なし」で報告してください:

1. 症状と根本原因が区別されているか
2. 成功基準が定量的・測定可能か（「改善する」「使いやすくする」になっていないか）
3. Out of Scope が「対象外にする理由」とセットで記載されているか
4. 各 R-xxx に優先度と根拠があるか
5. 前提条件と「崩れた場合のリスク」が記載されているか
6. 完了チェックリストの全項目が充足されているか

問題がある箇所は具体的な修正案を示すこと。
README.md への登録が必要な OQ があれば末尾にリストアップすること。
```

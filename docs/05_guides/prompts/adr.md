# プロンプト: 意思決定記録 (ADR-xxx)

> 対象ファイル: `docs/04_decisions/ADR-xxx_[name].md`

---

## 初稿生成

```
docs/SKILL.md を読んでから、
docs/04_decisions/ に ADR-[番号]_[name].md を新規作成してください。

## コンテキスト

意思決定のタイトル: [何を決めるか]
ADR-ID: ADR-[番号]

背景・制約:
[なぜこの決定が必要になったか。どんな制約・要求の中で判断するか。
 ソリューションをここに書かない]

検討している選択肢:
- 選択肢A: [名称と概要]
- 選択肢B: [名称と概要]
- 選択肢C: [名称と概要（あれば）]

重視する評価軸:
- [評価軸1]（重み: 高/中/低）: [定義]
- [評価軸2]（重み: 高/中/低）: [定義]
- [評価軸3]（重み: 高/中/低）: [定義]

現時点での傾き（あれば）: [選択肢X が有力 / 未定]

関連するドキュメント:
- [REQ-F-xxx / SPEC-xxx 等]

## 出力指示

- 評価軸を先に定義してから各選択肢を同じ軸で比較すること
- 採用・不採用を問わずすべての選択肢を記述すること
- 不採用の選択肢に「なぜ不採用か」を明記すること
- 受け入れたトレードオフを「あきらめること / 影響 / 緩和策」の形で明示すること
- 後続アクションは README.md の TASK-xxx と紐づける形で記載すること
- 再検討条件（どんな状況になったら見直すか）を必ず書くこと
- 不明点は OQ として記載し、README.md への登録を促すこと
```

## 選択肢の比較表生成

> 意思決定の前に選択肢を整理したいとき。ADR 作成の前段として使う。

```
docs/SKILL.md を読んでから、以下の選択肢を比較してください。

意思決定のテーマ: [何を決めるか]

選択肢:
- [選択肢A]: [概要]
- [選択肢B]: [概要]
- [選択肢C]: [概要（あれば）]

重視する評価軸:
- [評価軸1]（重み: 高/中/低）
- [評価軸2]（重み: 高/中/低）

制約・コンテキスト:
[チームの習熟度・既存技術スタック・スケジュール・予算等]

## 出力形式

1. 各選択肢を評価軸ごとに ◎/○/△/✗ で比較した表を生成する
2. 各評価の根拠を1〜2文で説明する
3. トレードオフのサマリーを示す
4. 推奨案と根拠を示す（ただし最終決定は人間が行う）

比較結果をもとに ADR を作成する場合は
docs/05_guides/prompts/adr.md の「初稿生成」プロンプトを使うこと。
```

## レビュー・抜け漏れチェック

```
docs/SKILL.md を読んでから、
docs/04_decisions/ADR-[番号]_[name].md をレビューしてください。

以下の観点で確認し、「問題あり / 要確認 / 問題なし」で報告してください:

1. 検討した選択肢が2つ以上記述されているか
2. 各選択肢が同じ評価軸で比較されているか
3. 不採用の選択肢に「なぜ不採用か」が明記されているか
4. 受け入れたトレードオフが「あきらめること」として明示されているか
   （ポジティブな影響だけを書いていないか）
5. 後続アクションが README.md の TASK-xxx と紐づいているか
6. 再検討条件が記述されているか
7. コンテキストセクションにソリューションが混入していないか
   （「何が問題か」と「どう解決するか」が混在していないか）

問題がある箇所は具体的な修正案を示すこと。
```

## 既存 ADR の supersede

> 過去の決定を覆す新しい ADR を作りたいとき。

```
docs/SKILL.md を読んでから、
docs/04_decisions/ADR-[既存番号]_[既存name].md を参照して、
この決定を supersede する新しい ADR を作成してください。

新しい ADR-ID: ADR-[新番号]

見直しの理由:
[再検討条件のどれが発動したか、または新たに何が判明したか]

新たに採用する方針:
[何に変えるか・概要]

## 出力指示

- 既存 ADR の frontmatter の superseded_by に新 ADR-ID を追記すること
- 新 ADR の related に既存 ADR-ID を記載すること
- 既存の意思決定からの「変更点」と「変更しない点」を明確にすること
```

## 粒度チェック（単体）

> 「これは1つのADRでいいか？」を判断したいとき。

```
docs/SKILL.md と docs/05_guides/granularity_guide.md を読んでから、
以下の意思決定の粒度を評価してください。

意思決定のタイトル: [タイトル]
決定事項（一文で）: [何を決めるか]
検討している選択肢: [選択肢A, 選択肢B, ...]
評価軸: [評価軸1, 評価軸2, ...]
後続アクション: [アクション1, アクション2, ...]

Rule ADR-1〜4 を適用して:
1. この意思決定をそのまま1つの ADR-xxx にすべきか
2. 分割すべき場合、どう分割するか（分割後の構造案と related の付け方を示すこと）
```

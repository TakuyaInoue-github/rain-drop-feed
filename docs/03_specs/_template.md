## 3. フロー定義

> **ルール:** 行を追加することでフローを表現する。
> `フロー種別` 列を必ず埋めること。空欄は未検討とみなす。
>
> | フロー種別 | 値 |
> |---|---|
> | `主系` | 正常に完了するメインのフロー |
> | `代替系` | 正常だが別ルートをたどるフロー |
> | `例外系` | エラー・異常・権限違反など失敗するフロー |
>
> **条件/トリガーの書き方（EARSキーワードの軽量適用）:** 先頭に条件の性質を示す
> キーワードを付けると曖昧さが減る。厳密な文法として強制する必要はない。
>
> | キーワード | 使う場面 |
> |---|---|
> | `WHEN` | ユーザー操作・外部イベントが引き金 |
> | `IF` | 入力・状態が特定条件を満たす（満たさない） |
> | `WHILE` | ある状態が継続している間 |
> | `WHERE` | 特定の設定・機能が有効な場合のみ |
> | (指定なし) | 常時成立する前提（正常系の既定条件など） |

| # | フロー種別 | 条件 / トリガー | アクター | 操作・イベント | システムの処理 | ユーザーへの表示 / レスポンス |
|---|---|---|---|---|---|---|
| 1 | 主系 | 正常な入力 | ユーザー | フォームを送信する | バリデーション → 保存 | 完了メッセージを表示し○○画面へ遷移 |
| 2 | 例外系 | IF 必須項目が未入力 | ユーザー | フォームを送信する | バリデーションエラー | 対象フィールド直下に「○○を入力してください」を赤字で表示。送信はしない |
| 3 | 例外系 | IF 入力値が最大長を超過 | ユーザー | フォームを送信する | バリデーションエラー | 「○○は△△文字以内で入力してください」を表示 |
| 4 | 例外系 | WHEN 未認証状態でアクセス | 未認証ユーザー | URLに直接アクセス | 認証チェック | ログイン画面へリダイレクト。ログイン後、元のURLへ戻す |
| 5 | 例外系 | WHEN 権限のないロールがアクセス | 一般ユーザー | 管理者専用操作を実行 | 認可チェック | 403エラー画面を表示 |
| 6 | 例外系 | WHILE 外部サービスがタイムアウト中 | システム | - | タイムアウト検知 → リトライ3回 | 「しばらく時間をおいて再試行してください」を表示。入力内容は保持する |
| 7 | 例外系 | WHEN 同一データへの同時更新が発生 | 複数ユーザー | 同時に保存を実行 | 楽観的ロック検知 | 「他のユーザーが更新しました。最新の内容を確認してください」を表示 |
| 8 | 代替系 | (代替フローの条件) | | | | |

> **確認チェック:** 以下の例外ケースをすべて検討したか？
> - [ ] 未認証アクセス
> - [ ] 権限違反アクセス
> - [ ] 必須項目未入力
> - [ ] 最大値・最小値超過
> - [ ] 空文字・NULL入力
> - [ ] 外部システムの障害・タイムアウト
> - [ ] 同時操作・競合
> - [ ] 対象リソースが存在しない (404)
> - [ ] 対象リソースが削除済み

## 4. 入出力定義

### 入力

> **注意:** `NULL・空文字の扱い` 列を必ず埋めること。「N/A」は不可。

| 項目名 | 型 | 必須 | 制約 | NULL・空文字の扱い | 備考 |
|---|---|---|---|---|---|
| (例) メールアドレス | string | Yes | RFC5322準拠, 255文字以内 | エラー: 「メールアドレスを入力してください」 | 前後の空白はトリムする |
| (例) 名前 | string | Yes | 100文字以内 | エラー: 「名前を入力してください」 | - |
| (例) 電話番号 | string | No | 数字・ハイフンのみ, 20文字以内 | NULL許容・保存する | 未入力の場合は null として保存 |

### 出力

| 項目名 | 型 | 内容 | 条件 |
|---|---|---|---|
| (例) ユーザーID | string (UUID v4) | 作成されたユーザーのID | 正常系のみ |
| (例) エラーコード | string | エラー識別コード | 例外系のみ |
| (例) エラーメッセージ | string | ユーザー向けメッセージ | 例外系のみ |

```
[METHOD] /path/to/endpoint

  {

  {
    "id": "uuid",

  }

    "error_code": "VALIDATION_ERROR",

      { "field": "email", "message": "有効なメールアドレスを入力してください" }

  { "error_code": "UNAUTHORIZED" }

  { "error_code": "FORBIDDEN" }

Response 404 (リソースなし):
  { "error_code": "NOT_FOUND" }

Response 409 (競合):
  { "error_code": "CONFLICT", "message": "他のユーザーが更新しました" }

Response 500 (サーバーエラー):
  { "error_code": "INTERNAL_SERVER_ERROR" }
```

## 10. テスト観点

> **ルール:** 以下の種別はすべて記述すること。省略する場合は「対象なし・理由:〜」と明記する。
>
> **反証可能性列について:** 「このテストは実装のどんな誤りを検出できるか」を一言添える。
> 書けない場合、そのテストはAC（受け入れ条件）の文言を言い換えているだけの
> トートロジーである疑いが強い。その場合はAC自体かテスト設計を見直すサインとして扱う。

| # | テスト観点 | 種別 | 対応AC | 反証可能性（どう壊せばレッドになるか） |
|---|---|---|---|---|
| T-001 | 正常系: 有効な入力で保存が成功すること | 機能テスト | AC-001 | 保存処理を呼ばない・呼び出し条件を反転すればレッド |
| T-002 | 異常系: 必須項目未入力でエラーメッセージが表示されること | バリデーション | AC-010 | 必須チェックを削除・条件を反転すればレッド |
| T-003 | 境界値: 最大文字数ちょうどで成功すること | 境界値テスト | AC-020 | 上限チェックの比較演算子を1文字ずらせばレッド |
| T-004 | 境界値: 最大文字数+1でエラーになること | 境界値テスト | AC-021 | 上限チェックの比較演算子を1文字ずらせばレッド |
| T-005 | 権限: 未認証でアクセスするとログイン画面へ遷移すること | 認証テスト | AC-030 | 認証チェックを削除・リダイレクト先を誤らせればレッド |
| T-006 | 権限: 権限のないロールで操作すると403になること | 認可テスト | AC-031 | 認可チェックを削除・ロール判定を反転すればレッド |
| T-007 | セキュリティ: SQLインジェクション文字列を入力しても安全に処理されること | セキュリティ | - | パラメータバインドを文字列連結に置き換えればレッド |
| T-008 | 負荷: 同時送信が発生した場合にデータ整合性が保たれること | 整合性テスト | - | 楽観的ロック・トランザクションを外せばレッド |

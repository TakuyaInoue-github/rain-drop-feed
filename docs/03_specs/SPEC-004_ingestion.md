## 1. 概要

評価済みエントリについて、補正後スコア（スコア + 情報源の重み）を算出し、閾値と比較して
投入対象を決め、Raindrop.io の指定コレクションへ1件ずつ POST してタグを付与する。
投入は 1 req/sec 以下に抑え、個別の失敗は他のエントリの投入を止めない。

**本仕様の範囲外:**

| 範囲外の内容 | 置き場 |
|---|---|
| エントリの評価そのもの（スコア・理由・提案タグの取得） | SPEC-003 |
| 投入結果の状態への記録（`ingested` / `final_score` の書き込み） | SPEC-002 |
| 投入件数・失敗件数のサマリ出力 | SPEC-006 |
| 終了コードの体系（値の定義） | SPEC-005（正典）。本仕様は `INGEST_ALL_FAILED` を**参照する**のみ |

> **粒度についての注記（Rule S-1 / S-2 / S-3）:** フロー定義表は 18 行で 15 行の目安を超えるが、
> **統合を維持する**。#1〜4 の判定群と #5〜18 の投入群は、いずれも「投入対象」という
> 単一の判定結果に対する一連の処理であり、独立した状態機械を持たない（Rule S-2 に該当しない）。
> 判定側だけを切り出すと `adjust` / `should_ingest` / `is_hot` の 3 関数に対して
> フロー 4 行の SPEC となり、Rule S-3（3行以下は統合）の水準に近い。また判定と投入を
> 分けると「補正後スコアが値域を超えうる」という性質（→ §4）が両 SPEC にまたがり、
> `#score-{n}` の n の定義（→ OQ-001）の置き場が決まらない。

## 2. 前提条件 (Preconditions)

| 前提条件 | 満たされない場合の挙動 |
|---|---|
| 収集レイヤーの認証情報（`RAINDROP_TOKEN`）が設定されていること | 起動時に検知し、フィード取得・評価を開始する前に終了する（→ フロー #14 / F-001 AC-030）。dry-run では続行する（→ フロー #4 / F-005 AC-030） |
| 投入先コレクション ID が設定されていること | 起動時に検知し、既定のコレクションへ投入せずに終了する（→ フロー #15 / F-001 AC-032） |
| 当該エントリの評価が成功しており、スコアが値域内の整数であること | 投入対象の判定を行わない。評価失敗として扱う（→ SPEC-003 / F-001 AC-029）。本仕様は `score` が `null` のエントリを受け取らない |
| 当該エントリの情報源に重みが定義されていること | 重み 0 として扱う（→ §4 入力定義） |
| 当該エントリが状態と突合済みで新規であること | 本仕様は突合を行わない（→ SPEC-002）。突合済みの集合のみを受け取る |

## 3. フロー定義

> 本仕様は無人 CLI のバッチ処理であり、対話的な画面を持たない。
> 「ユーザーへの表示 / レスポンス」列は **標準エラー出力への出力内容**、および
> 呼び出し元（`pipeline`）への戻り値を指す。サマリ（標準出力）は SPEC-006 が担う。

| # | フロー種別 | 条件 / トリガー | アクター | 操作・イベント | システムの処理 | ユーザーへの表示 / レスポンス |
|---|---|---|---|---|---|---|
| 1 | 主系 | 1件の評価が完了した | システム | 補正後スコアの算出 | `補正後スコア = スコア + 重み`（`domain.scoring.adjust`）。**値域 0〜10 に丸めない**（→ §4 の注記 / F-001 AC-005） | - |
| 2 | 主系 | IF 補正後スコア >= 閾値（既定 5） | システム | 投入可否の判定 | 投入対象とする（`domain.scoring.should_ingest` / F-001 AC-001・AC-020） | - |
| 3 | 主系 | 投入対象と判定された | システム | 投入 | タグ集合（→ §4 出力）を構築し、`POST /rest/v1/raindrop` を1回発行する（→ §8）。直前の投入から 1 秒未満なら差分だけ待つ（→ §7 / REQ-NF-001） | （標準エラー）`投入しました: {url}` |
| 4 | 代替系 | WHERE dry-run が指定されている | 運用者 | 実行 | 補正後スコアの算出と投入可否の判定は行うが、**HTTP リクエストを一切発行しない**。認証情報・コレクション ID が未設定でも中止しない（F-005 AC-001 / AC-030） | （標準出力）投入対象と判定された件数（→ SPEC-006） |
| 5 | 代替系 | IF 補正後スコア < 閾値 | システム | 投入可否の判定 | 投入しない。評価結果は記録される（→ SPEC-002 / F-001 AC-021） | - |
| 6 | 代替系 | IF 補正後スコア >= 高評価帯の境界（既定 7） | システム | タグ集合の構築 | `#hot` を追加する（`domain.scoring.is_hot` / F-001 AC-003） | - |
| 7 | 代替系 | IF 提案タグが空 | システム | タグ集合の構築 | 提案タグを加えずに投入を続行する（F-001 AC-027） | - |
| 8 | 代替系 | IF 情報源にタグが定義されていない | システム | タグ集合の構築 | 情報源タグを加えずに投入を続行する（F-001 AC-028） | - |
| 9 | 代替系 | IF 投入対象が 0 件 | システム | - | 1件も POST せず、**正常終了とする**（非0にしない → F-001 AC-014 括弧書き / AC-022） | （標準エラー）`投入対象がありません` |
| 10 | 例外系 | WHEN 応答が 429（レート制限） | システム | 投入 | 当該エントリを**レート制限による失敗**として、他の投入失敗と区別可能な理由コードで記録する（→ §4 出力 / F-001 AC-017）。本仕様ではリトライしない（→ OQ-002） | （標準エラー）`レート制限により投入できませんでした: {url}` |
| 11 | 例外系 | WHEN 応答が 401 / 403（認証失敗） | システム | 投入 | 当該エントリを失敗とし、以降の投入も同じ結果になるため**残りの投入対象を打ち切る**（→ OQ-003）。トークンの値はメッセージに含めない（F-001 AC-031 / REQ-NF-006） | （標準エラー）`収集レイヤーの認証に失敗しました（HTTP {status}）。以降の投入を中止します` |
| 12 | 例外系 | WHEN 応答が 4xx（400 / 404 等、429 / 401 / 403 を除く） | システム | 投入 | 当該エントリのみ失敗として記録し、次のエントリへ進む。リトライしない（同じ要求は再送しても通らない → §8） | （標準エラー）`投入に失敗しました: {url}（HTTP {status}）` |
| 13 | 例外系 | WHEN 応答が 5xx またはネットワーク障害 | システム | 投入 | 当該エントリのみ失敗として記録し、次のエントリへ進む（F-001 AC-012）。実行内リトライの要否は OQ-002 | （標準エラー）`投入に失敗しました: {url}（{理由}）` |
| 14 | 例外系 | IF 認証情報が未設定または空文字（通常実行） | 運用者 | 実行 | フィード取得・評価を開始する前に終了する（終了コード `CONFIG_ERROR` → SPEC-005 / F-001 AC-030） | （標準エラー）`環境変数 RAINDROP_TOKEN が設定されていません` |
| 15 | 例外系 | IF 投入先コレクション ID が未設定・空文字・整数として解釈できない（通常実行） | 運用者 | 実行 | 同上。**既定のコレクション（`$id: -1` = Unsorted）へフォールバックしない**（F-001 AC-032） | （標準エラー）`環境変数 RAINDROP_COLLECTION_ID が設定されていないか、整数ではありません` |
| 16 | 例外系 | WHILE 応答が規定時間内に返らない | システム | 投入 | タイムアウトとして打ち切り、当該エントリを失敗として記録して次へ進む（F-001 AC-016 / REQ-NF-004） | （標準エラー）`投入がタイムアウトしました: {url}` |
| 17 | 例外系 | IF 投入対象が1件以上あり、その**全件**が失敗した | システム | 投入完了時 | 実行を失敗として終了する（終了コード `INGEST_ALL_FAILED` → SPEC-005 / F-001 AC-014・F-004 AC-016）。状態の記録（SPEC-002）は先に完了させる | （標準エラー）`投入対象 {n}件がすべて失敗しました` |
| 18 | 例外系 | WHEN 同一 URL が Raindrop 上に既に存在する | システム | 投入 | **重複として扱わず、そのまま投入する。** 重複排除は状態との突合（SPEC-002）のみが担い、収集レイヤー側の内容は判定に用いない（→ ADR-002 選択肢 D の不採用理由）。運用者が Raindrop 上で手動削除した記事は再投入されない（状態に残るため） | 出力なし（正常系と区別しない） |

> **確認チェック:** 例外系9項目の検討結果
> - [x] **未認証アクセス** — フロー #14（トークン未設定・起動時）／フロー #11（トークンが無効・投入時の 401）
> - [x] **権限違反アクセス** — フロー #11（403。トークンが当該コレクションへの権限を持たない場合を含む）。本システム自体は認証・認可機構を持たず、権限判断は Raindrop 側に委ねる（REQ-NF-005）
> - [x] **必須項目未入力** — フロー #12（`link` を欠く要求は 400。`link` は §5 で送信前に検証するため、通常この経路には至らない）／フロー #15（コレクション ID）
> - [x] **最大値・最小値超過** — §5 のタグ長・タイトル長・タグ件数の切り詰め（送信前）。補正後スコアの値域超過は**エラーではない**（→ §4 の注記）
> - [x] **空文字・NULL入力** — フロー #14 / #15（秘匿値）。`title` / `excerpt` / タグの空値は §5 で除去して送信する
> - [x] **外部システムの障害** — フロー #13（5xx・ネットワーク障害）
> - [x] **タイムアウト** — フロー #16
> - [x] **同時操作・競合** — フロー #18。本仕様は Raindrop 側の状態を読まないため、他の実行や運用者の手動操作と競合しない（作成のみで更新・削除を行わない → F-001 Out of Scope）。実行の同時起動そのものの扱いは SPEC-002 フロー #17
> - [x] **対象リソースが存在しない** — フロー #12（存在しないコレクション ID を指定した場合の 404）
> - [x] **対象リソースが削除済み** — フロー #18。運用者が Raindrop 上で削除した記事は、状態側に記録が残るため再投入されない（F-001 Out of Scope「投入済みエントリの更新・削除」と整合）

## 4. 入出力定義

### 入力

1件の投入判定・投入に与える入力。`domain` 層は下表の補完済みの値のみを扱う。

| 項目名 | 型 | 必須 | 制約 | NULL・空文字の扱い | 備考 |
|---|---|---|---|---|---|
| `score` | integer | Yes | 0〜10 の整数（`is_valid_score` を通過済み） | **本仕様には到達しない。** `null`・範囲外は評価失敗として SPEC-003 で処理される（F-001 AC-029） | 補正前のスコア |
| `weight` | integer | No | -1 / 0 / +1 を想定するが値域は制約しない | 欠落・NULL は 0 として扱う（補正なしと同義） | `feeds.yaml` の `weight` |
| `url` | string | Yes | http/https スキームであること | **空文字・NULL なら投入せず失敗として記録する**（`link` が Raindrop の必須項目のため → §5） | 投入先の `link` |
| `title` | string | No | 送信前に切り詰める（→ §5） | 空文字のまま送信する（Raindrop 側で `link` から補完される → §8 `pleaseParse`） | - |
| `summary` | string | No | 送信前に切り詰める（→ §5） | 空文字のまま送信する（`excerpt` を空で送る） | F-001 AC-023 の要約欠落と整合 |
| `suggested_tags` | array\<string\> | No | 各要素は空でない文字列 | 欠落・NULL・空配列は「提案タグなし」として扱い投入を続行する（フロー #7 / F-001 AC-027） | 評価が返したタグ |
| `source_tags` | array\<string\> | No | 同上 | 欠落・NULL・空配列は「情報源タグなし」として扱い投入を続行する（フロー #8 / F-001 AC-028） | `feeds.yaml` の `tags` |
| `RAINDROP_TOKEN` | string | Yes（通常実行） | 空でないこと | 未設定・空文字なら起動時に終了する（フロー #14）。dry-run では未設定でも続行する | 値をログ・エラーメッセージに出力しない（F-001 AC-031） |
| `RAINDROP_COLLECTION_ID` | string → integer | Yes（通常実行） | 整数として解釈できること | 未設定・空文字・非整数なら起動時に終了する（フロー #15）。**既定値へフォールバックしない** | 値をサマリに出力しない（F-004 AC-030） |
| 閾値 | integer | No | - | 未指定なら既定 5（REQ-F-005） | 変更には運用者の合意を要する |
| 高評価帯の境界 | integer | No | - | 未指定なら既定 7（REQ-F-006） | 同上 |

> **補正後スコアの値域についての注記:** `補正後スコア = score + weight` は **0〜10 を超えうる**
> （`score=10, weight=+1` → 11、`score=0, weight=-1` → -1）。これを 0〜10 に丸めないのは、
> 丸めると重みが端で効かなくなり（10 と 11 が同じ扱いになり）、REQ-F-004 の
> 「重みを加算した値を判定に用いる」が端点で成立しなくなるため。値域超過はエラーではなく
> 正常な結果であり、閾値・高評価帯との比較にはそのまま用いる。
> **`#score-{n}` の n にどちらを使うかは OQ-001。**

### 出力

| 項目名 | 型 | 内容 | 条件 |
|---|---|---|---|
| 補正後スコア | integer | `score + weight`。値域を超えうる | 常時 |
| 投入対象か | boolean | `補正後スコア >= 閾値` | 常時 |
| 高評価帯か | boolean | `補正後スコア >= 高評価帯の境界` | 投入対象のときのみ意味を持つ |
| 付与タグ集合 | list\<string\> | `#auto` + `#score-{n}` + （高評価帯なら `#hot`）+ 情報源タグ + 提案タグ。重複を除去し、§5 の正規化を適用した順序付き集合 | 投入対象のときのみ |
| 投入成否 | boolean | 当該エントリの POST が成功したか | 通常実行かつ投入対象のときのみ。dry-run では常に「投入していない」 |
| 失敗理由コード | enum | `rate_limited` / `unauthorized` / `client_error` / `server_error` / `timeout` / `network_error` / `invalid_link` | 投入に失敗したときのみ。**`rate_limited` を他と区別可能にすることが F-001 AC-017 の要件**（→ OQ-002） |
| 投入対象件数 | integer | 補正後スコアが閾値以上と判定された件数 | 常時（0件を含む）。dry-run ではこれがサマリの「投入」欄になる（F-005 AC-003） |
| 投入成功件数 / 失敗件数 | integer | 実際に POST が成功 / 失敗した件数 | 通常実行のみ。フロー #17 の判定に用いる |

## 5. バリデーション仕様

> フロー定義表（§3）が「呼び出しの結果どう分岐するか」を定めるのに対し、本節は
> **送信前にローカルで行う整形・拒否**のみを扱う。両者に同じ条件を重複して書かない。

| 項目 | ルール | タイミング | エラーメッセージ |
|---|---|---|---|
| `url` | 空でなく、`http://` または `https://` で始まること | 送信前 | `投入できない URL のためスキップします: {url}`（理由コード `invalid_link`） |
| `title` | 送信前に先頭 500 文字へ切り詰める | 送信前 | 出力なし（切り詰めは正常な整形。件数のみ verbose ログに出す） |
| `excerpt`（要約） | 送信前に先頭 1,000 文字へ切り詰める | 送信前 | 同上 |
| タグ（各要素） | 前後の空白を除去し、空文字になった要素を捨てる。`#` で始まる場合は先頭の `#` を除去する（Raindrop の `tags` はプレフィックスなしの文字列配列として送る → §8 / **OQ-004**） | 送信前 | 出力なし |
| タグ（各要素の長さ） | 先頭 50 文字へ切り詰める | 送信前 | 出力なし |
| タグ集合 | 大文字小文字を区別せず重複を除去する。除去後 30 件を超える分は、`#auto` → `#score-{n}` → `#hot` → 情報源タグ → 提案タグ の優先順で先頭から採り、超過分を捨てる | 送信前 | 出力なし（超過時のみ verbose ログ） |
| `collection.$id` | 整数であること。`-1`（Unsorted）・`0`・負値を**受け付けない** | 起動時 | `環境変数 RAINDROP_COLLECTION_ID が設定されていないか、整数ではありません` |

> **切り詰め値の根拠についての注記:** 上表の 500 / 1,000 / 50 / 30 は Raindrop が公開して
> いる上限ではなく、**要求のサイズを予測可能に保つための本システム側の自主的な上限**である
> （全文配信フィードは実測で 9,238 文字 → REQ-NF-002a）。Raindrop 側の実上限は未確認であり、
> 400 が返る経路（フロー #12）は残る。実上限の確認と値の確定は **OQ-004**。

## 6. 状態遷移

**対象なし** — 投入は作成のみを行い、投入済みエントリの更新・削除・再スコアリングを
行わない（F-001 Out of Scope）。1件のエントリは「投入する / しない」の一度きりの判定を
受けるのみで、Raindrop 側のエンティティに本システムが観測・遷移させる状態を持たない。

処理済みエントリの状態遷移（未知 / 評価失敗 / 評価済み）は SPEC-002 §6 が定義する。

## 7. 非機能仕様（この仕様固有）

| 観点 | 仕様 | 対応要件 |
|---|---|---|
| レート制御 | **1 req/sec 以下**。投入は逐次実行し、直前の要求の開始時刻から 1 秒が経過するまで次の要求を発行しない（並列化しない）。Raindrop の 120 req/min = 2 req/sec に対し 50% の余裕を取る。週次の投入数 20〜30 件では所要 30 秒未満で、実行時間目標を圧迫しない | REQ-NF-001 |
| タイムアウト | 1件の投入あたりの HTTP タイムアウトを設定する（**具体値は OQ-005**）。無期限に待たない | REQ-NF-004, F-001 AC-016 |
| 部分障害の分離 | 1件の投入失敗が他のエントリの投入を止めない（例外を捕捉して次へ進む）。ただし 401 / 403 は残りも同じ結果になるため打ち切る（フロー #11） | REQ-NF-004, F-001 AC-012 |
| 通信の暗号化 | エンドポイントは HTTPS 固定。証明書検証を無効化しない | REQ-NF-006 |
| 秘匿情報の非出力 | `RAINDROP_TOKEN` と投入先コレクション ID を、ログ・サマリ・エラーメッセージ・例外の文字列表現に含めない。HTTP クライアントの例外は要求ヘッダを含みうるため、**捕捉した例外をそのまま出力せず、理由コードと HTTP ステータスのみを出力する** | REQ-NF-006, F-001 AC-031, F-004 AC-030 / AC-031 |
| 冪等性 | POST は冪等でない。重複投入を防ぐのは状態との突合（SPEC-002）のみであり、本仕様は同一 URL を2回渡されれば2回投入する。**呼び出し側が突合済みの集合を渡す責任を持つ** | R-002, ADR-005 / TASK-051 |
| 撤退可能性 | 全投入エントリに `#auto` を付与し、手動登録分と機械的に区別できるようにする（要件定義 §7 のロールバック条件）。**タグによる一括削除が Raindrop 側で可能かは未確認**（→ OQ-006 / TASK-045） | 要件定義 §7 |

## 8. API仕様

> 本仕様は Raindrop.io API を外部システムとして**呼び出す**（公開はしない）。
> 一次情報: [Raindrop.io Developer Docs](https://developer.raindrop.io/)（2026-07-27 確認）。

### 投入（1件の作成）

```
POST https://api.raindrop.io/rest/v1/raindrop

Request Headers:
  Authorization: Bearer {RAINDROP_TOKEN}
  Content-Type: application/json

Request Body:
  {
    "link":        "https://example.com/posts/foo",   // 必須。空文字・非 http(s) は送信しない (§5)
    "title":       "記事タイトル",                     // 500文字へ切り詰め (§5)
    "excerpt":     "フィードの要約",                   // 1,000文字へ切り詰め (§5)
    "tags":        ["auto", "score-8", "hot", "aws"], // '#' なしの文字列配列 (§5)
    "collection":  { "$id": 12345678 },               // RAINDROP_COLLECTION_ID
    "pleaseParse": {}                                 // メタデータの補完を Raindrop 側に任せる
  }

Response 200 (正常系):
  {
    "result": true,
    "item": { "_id": 987654321, "link": "...", "tags": [...], ... }
  }
  → item._id を得るが、本システムは保持しない（更新・削除を行わないため → F-001 Out of Scope）

Response 400 (要求が不正):
  → 当該エントリのみ失敗 (理由コード client_error)。リトライしない (フロー #12)

Response 401 (トークンが無効・失効):
  → 以降の投入を打ち切る (理由コード unauthorized。フロー #11)

Response 403 (当該コレクションへの権限がない):
  → 401 と同じ扱い (フロー #11)

Response 404 (コレクションが存在しない):
  → 当該エントリのみ失敗 (理由コード client_error。フロー #12)

Response 429 (レート制限):
  → 理由コード rate_limited。他の失敗と区別して記録する (フロー #10 / F-001 AC-017)

Response 5xx (サーバーエラー):
  → 当該エントリのみ失敗 (理由コード server_error。フロー #13)
```

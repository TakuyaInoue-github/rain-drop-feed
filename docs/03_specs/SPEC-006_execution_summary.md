## 1. 概要

1回の実行で各段階（SPEC-001 取得 / SPEC-002 突合・記録 / SPEC-003 評価 /
SPEC-004 投入）が返した結果を集約し、**標準出力へ人間可読のサマリとして出力する**。
処理経過のログは標準エラーへ出し、サマリと混ざらないようにする（F-004 AC-005）。

**本仕様はサマリの表示内容の正典である。** 集計値そのものは各 SPEC が生成し、
本仕様は**受け取った値を並べるだけで、再計算も再解釈もしない**。

> **なぜ「集計しない」ことを明記するか:** サマリ側で件数を数え直すと、各 SPEC が
> 定めた定義（たとえば SPEC-004 の「未試行件数は成功にも失敗にも数えない」）と
> ずれた第二の定義が生まれる。ずれても出力は一応それらしく見えるため、
> **無人実行では誰も気づかない**。本仕様は `RunSummary` の値をそのまま表示する。
>
> **唯一の例外は概況の「取得」件数**で、これは `sources[].fetched` の合計として
> 本仕様が算出する。情報源別の内訳と必ず一致すべき値であり、独立したフィールドで
> 受け取ると両者がずれた出力を検出できないため（→ §9）。

**本仕様の範囲外:**

| 範囲外の内容 | 置き場 |
|---|---|
| 各集計値の定義・算出（何を成功と数えるか等） | SPEC-001 / 002 / 003 / 004 |
| 終了コードの決定 | SPEC-005 §5（正典） |
| 前回実行の記録（`runs.jsonl`）の読み書き | SPEC-002 §4 |
| 詳細ログ（`--verbose`）の内容 | 各 SPEC。本仕様は**サマリが verbose で変化しないこと**のみ規定する（F-004 AC-007） |
| dry-run で収集レイヤーの秘匿情報が未設定である旨の警告（F-005 AC-030a） | SPEC-005 フロー #6（標準エラー）。**サマリ本体へ出すべきかは OQ-007** |

> **粒度についての注記（Rule S-1 / S-3 / S-4）:** フロー定義表は16行で目安内。
> F-004（サマリ）と F-005（dry-run）の2つの機能が本仕様を共有する（Rule S-4）。
> dry-run 用のサマリ仕様を分けないのは、**差分が4点のみ**（見出しの標識・投入欄の
> 意味・前回比の欠落・記事明細）で、分けると同一の項目表が2箇所に複製されるため（Rule B-3）。
> 逆に「サマリの整形」と「出力先の振り分け」を分けないのは、後者が2行にしかならず
> Rule S-3 に反するため。

## 2. 前提条件 (Preconditions)

| 前提条件 | 満たされない場合の挙動 |
|---|---|
| 起動時検証を通過していること | サマリを出力しない。`CONFIG_ERROR` で終了する（SPEC-005 フロー #8〜13）。**この場合サマリは1行も出ない**（→ §3 の注記） |
| `RunSummary`（`contract/model.py`）が構築されていること | 本仕様は既定値のみの `RunSummary` を受け取り、全項目を 0 として出力する（フロー #14） |
| 標準出力が書き込み可能であること | 出力に失敗しても実行の終了コードを変えない（フロー #16） |

> **`RunSummary` は実行開始時に構築され、各段階が埋める。** 途中で例外が発生しても
> それまでに埋まった範囲が残るため、AC-013（部分的なサマリ）が成立する。
> 各段階の完了を待って最後に組み立てる設計では、異常終了時に何も出せない。

## 3. フロー定義

> 本仕様は無人 CLI のバッチ処理であり、対話的な画面を持たない。
> 「ユーザーへの表示 / レスポンス」列は**標準出力への出力内容**を指す。
> 標準エラーへの出力は明示する。

| # | フロー種別 | 条件 / トリガー | アクター | 操作・イベント | システムの処理 | ユーザーへの表示 / レスポンス |
|---|---|---|---|---|---|---|
| 1 | 主系 | 処理本体の完了時 | システム | サマリの出力 | `RunSummary` の各項目を §4 の順序で整形する。**値の再計算は行わない** | （標準出力）サマリ全体（→ §9） |
| 2 | 主系 | サマリの先頭 | システム | 見出しの出力 | 実行時刻（UTC）と実行種別を出す | `=== feed-triage 実行サマリ (2026-07-28T09:00:00Z) ===` |
| 3 | 主系 | 概況の出力 | システム | 件数の出力 | 取得数・新規数・評価数・投入数を出す（F-004 AC-001） | `取得 42 件 / 新規 8 件 / 評価 8 件 / 投入 3 件` |
| 4 | 主系 | 情報源別の出力 | システム | 情報源ごとの行を出す | SPEC-001 が返した `SourceOutcome` を**定義順のまま**1情報源1行で出す（F-004 AC-003） | `  jane-street      5 件 (前回 4)` |
| 5 | 主系 | WHERE 前回の実行記録が存在する | システム | 前回比の出力 | `runs.jsonl` の直近行の `sources` と対比して出す（F-004 AC-003a） | 上記の `(前回 4)` 部分 |
| 6 | 主系 | スコア分布の出力 | システム | 分布の出力 | 評価に成功した記事のスコア別件数を**昇順**で出す（F-004 AC-002） | `スコア分布: 3:2 5:3 7:2 9:1` |
| 7 | 主系 | コストの出力 | システム | コストと件数の出力 | 当該実行の評価コストと評価件数を出す（F-004 AC-004） | `評価コスト: $0.021 (8 件)` |
| 8 | 主系 | 経過期間の出力 | システム | 前回実行からの経過の出力 | 直近の `run_at` との差を週数で出す（F-004 AC-008 / F-002 AC-015） | `前回実行から 1.0 週` |
| 9 | 代替系 | WHERE `--dry-run` が指定されている | システム | サマリの出力 | 見出しに標識を付け、投入欄を**投入対象件数**の意味に変える（F-005 AC-003 / AC-005）。前回比・経過期間は出さない（→ §4 の注記） | `=== feed-triage 実行サマリ [DRY-RUN] (...) ===` / `投入対象 3 件 (投入は行っていません)` |
| 10 | 代替系 | WHERE `--dry-run` かつ評価済みの記事がある | システム | 明細の出力 | 記事ごとに URL・スコア・投入可否を出す（F-005 AC-002）。**通常実行では出さない** | `  [投入] 8 https://example.com/a` |
| 11 | 代替系 | WHERE `--verbose` が指定されている | システム | サマリの出力 | **サマリの内容を変えない**（F-004 AC-007）。詳細化されるのは標準エラー側のみ | 通常実行と同一のサマリ |
| 12 | 代替系 | WHERE 前回の実行記録が存在しない（初回実行） | システム | 前回比の出力 | 前回比と経過期間を `-` として出す。**行を省略しない** | `  jane-street      5 件 (前回 -)` / `前回実行から: - (初回)` |
| 13 | 例外系 | IF 取得に失敗した情報源がある | システム | 情報源別の出力 | 件数の代わりに失敗を示し、理由を併記する（F-004 AC-010） | `  snowflake-blog   取得失敗 (HTTP 404)` |
| 14 | 例外系 | IF 全情報源の取得に失敗した | システム | 概況の出力 | **全件失敗である旨を明示する**（F-004 AC-014）。個別行だけでは全滅と一部失敗が判別しにくいため | `**全 13 情報源の取得に失敗しました**` |
| 15 | 例外系 | IF 処理済み記録の永続化に失敗した | システム | 警告の出力 | 失敗の事実と、**次回実行で重複投入が起こりうる**旨を出す（F-004 AC-015） | `**記録の永続化に失敗しました: {理由}。次回実行で重複投入が発生しうるため、状態ブランチを確認してください**` |
| 16 | 例外系 | IF 処理途中の例外により終了した | システム | サマリの出力 | **それまでに埋まった範囲を出力する**（F-004 AC-013）。未到達の段階は 0 として出す | 見出し行の末尾に `（未完了）` を付す（→ §9） |
| 17 | 例外系 | IF POST を試行した件数が1件以上あり、その全件が失敗した | システム | 概況の出力 | **投入の全件失敗である旨を明示する**（F-004 AC-016）。分母は試行件数であり、**401/403 の打ち切りで未試行となった分を含めない**（SPEC-004 フロー #11 / #15）。dry-run では発生しない | `**投入対象 {n} 件がすべて失敗しました**` |

> **確認チェック:** 例外系9項目の検討結果
> - [x] **未認証アクセス** — **本仕様では扱わない。** 秘匿情報の未設定は SPEC-005 が起動時に弾き、サマリを出力する段階に到達しない（§2）。投入時の 401/403 は SPEC-004 の失敗理由コードとして本仕様に届き、フロー #13 と同じ形式で出力される
> - [x] **権限違反アクセス** — 同上。状態ブランチへの書き込み権限不足はフロー #15 に集約される
> - [x] **必須項目未入力** — **対象なし。** 本仕様の入力は `RunSummary` のみで、運用者からの入力を受け取らない。欠落項目は `contract/model.py` の既定値で埋まる（フロー #14）
> - [x] **最大値・最小値超過** — フロー #10（dry-run の明細行数）。**上限を設けない** → §5 および OQ-002
> - [x] **空文字・NULL入力** — §4 の入力表。`source_name` 空文字・`cost_usd` 0.0・`weeks_since_previous_run` null をそれぞれ規定する
> - [x] **外部システムの障害** — フロー #13 / #14（取得失敗）・#15（永続化失敗）。投入失敗は §4 の失敗理由コード別内訳として出力する
> - [x] **タイムアウト** — フロー #13 と同じ扱い。SPEC-001 / SPEC-004 が理由コードに落としたものを表示するのみ
> - [x] **同時操作・競合** — **本仕様では発生しない。** サマリの出力は当該プロセスの標準出力への書き込みのみ。状態の競合は SPEC-002 フロー #17 / #18 が扱い、結果はフロー #15 に届く
> - [x] **対象リソースが存在しない** — フロー #12（前回の実行記録がない初回実行）
> - [x] **対象リソースが削除済み** — 同上。`runs.jsonl` が失われた場合も初回実行と同じ扱いにする（前回比を出せないだけで、実行は継続する）

> **起動時検証で失敗した実行にサマリを出さない理由:** F-004 AC-013 は「処理途中の
> 例外」と「永続化の失敗」を対象としており、起動時検証の失敗を含まない。設定不備の
> 段階では取得も評価も行われておらず、**全項目 0 のサマリは「実行したが何も
> 取れなかった」実行と区別できない**。原因は標準エラーのメッセージと `CONFIG_ERROR`
> が伝える（SPEC-005 フロー #8〜13）。

## 4. 入出力定義

### 入力

`RunSummary`（`contract/model.py`）。**各項目の定義は生成元の SPEC が持ち、本仕様は
表示のみを定める。** 欠落は `contract` 層の既定値で補完済みである。

| 項目名 | 型 | 必須 | 制約 | NULL・空文字の扱い | 備考 |
|---|---|---|---|---|---|
| `sources` | list\<SourceOutcome\> | Yes | 定義順を保持する | **空リストは「情報源の定義が0件」を意味する**（F-004 AC-023）。専用の文言を出す（→ §5） | 生成元: SPEC-001 |
| `sources[].source_name` | string | Yes | - | 空文字なら `(名称なし)` と表示する。行は省略しない | 空文字は SPEC-005 の起動時検証が弾くため通常は到達しない |
| `sources[].fetched` | integer | Yes | 0 以上 | 0 でも**行を省略しない**（F-004 AC-022） | - |
| `sources[].error` | string \| null | No | - | `null` は成功を意味する。非 null なら件数の代わりに失敗を表示する（フロー #13） | - |
| `new_entries` | integer | Yes | 0 以上 | 0 でも明示的に出力する（F-004 AC-020） | 生成元: SPEC-002 |
| `evaluated` | integer | Yes | 0 以上 | 同上 | 評価を**試みた**件数。生成元: SPEC-003 |
| `evaluation_failures` | integer | Yes | 0 以上 | 0 なら行を省略してよい（→ §5） | F-004 AC-011 |
| `abandoned` | integer | Yes | 0 以上 | 同上 | 失敗上限に達し再評価されなくなった件数。**`evaluation_failures` と別行で出す**（F-004 AC-011a） |
| `ingested` | integer | Yes | 0 以上 | 0 でも明示的に出力する（F-004 AC-021） | 通常実行では投入成功件数、dry-run では投入対象件数（→ §5） |
| `ingest_attempted` | integer | Yes | 0 以上 | 0 は「投入対象が0件」を意味する。全件失敗の判定に用いる（フロー #17） | **`ingest_unattempted` を含まない**（SPEC-004 フロー #15）。生成元: SPEC-004 |
| `ingest_failures` | integer | Yes | 0 以上 | 0 なら行を省略してよい | F-004 AC-012。生成元: SPEC-004 |
| `ingest_failure_reasons` | dict\<string, integer\> | No | キーは SPEC-004 の失敗理由コード | 空辞書なら内訳を出さない | **本仕様で追加する**（→ §4 の注記） |
| `ingest_unattempted` | integer | No | 0 以上 | 0 なら行を省略してよい | 401/403 打ち切りによる未試行件数。**成功にも失敗にも数えない**（SPEC-004 §4） |
| `deferred` | integer | Yes | 0 以上 | 0 なら行を省略してよい | 上限超過による持ち越し（F-004 AC-004a） |
| `score_distribution` | dict\<integer, integer\> | Yes | キーはスコア値 | **空辞書は「評価に成功した記事が0件」を意味する**（F-004 AC-024）。専用の文言を出す（→ §5） | 生成元: SPEC-003 |
| `cost_usd` | float | Yes | 0.0 以上 | `evaluated == 0` のときの 0.0 は「0 件評価」を意味する。**`evaluated > 0` かつ 0.0 は算出失敗**であり §5 の警告対象 | API 応答の `usage` から算出する（OQ-001 で決定）。生成元: SPEC-005 |
| `dry_run` | boolean | Yes | - | `false` が通常実行 | 生成元: SPEC-005 `RunOptions` |
| `state_persist_error` | string \| null | No | - | `null` は永続化成功。非 null ならフロー #15 の警告を出す | 生成元: SPEC-002 |
| `weeks_since_previous_run` | float \| null | No | 0.0 以上 | **`null` は初回実行**（フロー #12）。`-` と表示する | 生成元: SPEC-002 の直前の実行記録 |
| `previous_sources` | dict\<string, integer\> | No | 情報源名 → 前回の取得件数 | 空辞書・`null` は初回実行として `-` を表示する | **本仕様で追加する**。生成元: SPEC-002 の `RunRecord.sources` |
| `entries` | list\<EntryVerdict\> | No | dry-run のときのみ非空 | 空リストなら明細を出さない | **本仕様で追加する**（F-005 AC-002 の供給元） |
| `completed` | boolean | No | - | `false` なら `（未完了）` の標識を付ける（フロー #16） | **本仕様で追加する** |

> **`contract/model.py` へ追加する項目（6件）:** `ingest_attempted` /
> `ingest_failure_reasons` / `ingest_unattempted` / `previous_sources` / `entries` /
> `completed`。
> いずれも **F-004 / F-005 の AC が要求しているが `RunSummary` に受け口がない**もので、
> 本仕様の執筆・独立レビューで判明した。対応する AC は順に AC-016（投入の全件失敗）・
> AC-012（失敗理由の識別）・
> SPEC-004 §4（未試行件数）・AC-003a（前回比）・F-005 AC-002（明細）・AC-013（部分出力）。

#### `EntryVerdict`（dry-run の明細行）

| 項目名 | 型 | 必須 | 制約 | NULL・空文字の扱い | 備考 |
|---|---|---|---|---|---|
| `url` | string | Yes | - | 空文字は到達しない（SPEC-002 が `url` 欠落行をスキップ済み） | 記事の識別子（F-005 AC-002） |
| `title` | string | No | 表示時に切り詰める（→ §5） | 空文字なら URL のみ表示する | - |
| `final_score` | integer \| null | Yes | 値域を超えうる（SPEC-004 §4） | `null` は評価失敗。`-` と表示する | **丸めない**（SPEC-004 の値域規定に従う） |
| `will_ingest` | boolean | Yes | - | - | `final_score >= 閾値`。SPEC-004 が判定した値をそのまま用いる |

### 出力

| 項目名 | 型 | 内容 | 条件 |
|---|---|---|---|
| サマリ本文 | string（複数行） | §9 の書式に従う人間可読のテキスト | 常時（標準出力） |
| 警告行 | string | 永続化失敗・全情報源失敗・未完了の標識 | 該当時のみ。**サマリ本文の一部として標準出力に出す**（標準エラーではない） |

> **警告を標準エラーへ出さない理由:** F-004 AC-005 は「サマリが単独で取り出せる」
> ことを求めており、AC-014 / AC-015 は**その事実がサマリで識別できる**ことを求める。
> 標準エラーへ分離すると `> summary.txt` でリダイレクトしたサマリから警告が消え、
> 両 AC を同時に満たせない。処理経過のログのみが標準エラーである。

## 5. バリデーション仕様

> 本仕様は運用者からの入力を受け取らないため、ここでの「検証」は
> **表示前の整形と、値の意味の解釈**を指す。

| 項目 | ルール | タイミング | エラーメッセージ |
|---|---|---|---|
| `sources` | 空リストなら情報源の定義が0件である旨を出す（F-004 AC-023） | 整形時 | `情報源が定義されていません。feeds.yaml を確認してください` |
| `sources[].error` | 非 null の要素数が `len(sources)` と等しく、かつ 1 以上なら全件失敗の警告を出す（F-004 AC-014） | 整形時 | `**全 {n} 情報源の取得に失敗しました**` |
| `ingest_attempted` | 1 以上、かつ `ingested == 0` なら投入の全件失敗の警告を出す（F-004 AC-016）。**dry-run では判定しない** | 整形時 | `**投入対象 {n} 件がすべて失敗しました**` |
| `sources[].source_name` | 表示幅を揃えるため右詰めする。**切り詰めない** | 整形時 | 出力なし（`feeds.yaml` の `name` は運用者が制御する値であり、切り詰めると情報源を識別できなくなる） |
| `score_distribution` | 空辞書なら評価成功0件である旨を出す（F-004 AC-024） | 整形時 | `スコア分布: (評価に成功した記事がありません)` |
| `score_distribution` | キーが1種類のみ、かつ評価成功が2件以上なら縮退の警告を出す（F-004 AC-024a） | 整形時 | `**スコア分布が全件同一値 ({score}) です。トリアージ基準の破損またはモデル誤指定を疑ってください**` |
| `cost_usd` | 小数第3位まで表示する（$0.001 単位） | 整形時 | 出力なし。REQ-NF-002a の月上限 $10 に対し、週あたりの桁を判断できる精度 |
| `cost_usd` | `evaluated` が 1 以上、かつ 0.0 なら算出失敗の警告を出す（OQ-001） | 整形時 | `  コストを算出できませんでした（応答からトークン数を取得できていません）` |
| `weeks_since_previous_run` | 小数第1位まで表示する。`null` は `-` | 整形時 | 出力なし |
| `weeks_since_previous_run` | 2.0 以上なら定期実行の不発火を疑う旨を併記する（F-002 AC-015） | 整形時 | `前回実行から {n} 週 **（定期実行が起動しなかった可能性があります）**` |
| `entries[].title` | 表示時に先頭 60 文字へ切り詰める | 整形時 | 出力なし（明細は1行1記事のため。URL は切り詰めない — 識別子であり、切ると記事を特定できない） |
| すべての出力 | 秘匿情報（`RAINDROP_TOKEN` / `RAINDROP_COLLECTION_ID` / `ANTHROPIC_API_KEY`）を含めないこと（F-004 AC-030 / AC-031） | 整形時 | 出力なし。**型で防ぐ** — `RunSummary` はこれらの値を保持しない（→ §7） |

> **`評価コスト: $X (n 件)` の n はコストの母集団と一致しない。** `n` は
> `evaluated`（状態に記録した件数）だが、コストは**記録しなかった件も含めて**
> 計上する — API 応答が返っていればトークンは消費済みであり、記録の可否で
> 除くと実費より小さく出るため（REQ-NF-002a の検知が目的）。したがって
> API 障害のみで終わった実行は `評価コスト: $0.675 (0 件)` の形になりうる。
> 同時に出る失敗理由の行と併せて読むこと。
>
> **`cost_usd` は実費の下限値である。** Anthropic SDK の内部リトライ
> （`max_retries`）による再送分は最終応答の `usage` に現れないため計上できない。
> 実請求と突き合わせる際は、この分だけ下振れすることを前提とする。

> **`score_distribution` の縮退判定で「2件以上」を条件にする理由:** 評価成功が1件の
> 場合は必然的に全件同一値になるが、これは異常ではない。1件でも警告すると、
> 新着が少ない週に毎回警告が出て**警告そのものが無視されるようになる**。

### dry-run 時の差分（**通常実行との差はこの4点のみ**）

| 項目 | 通常実行 | dry-run | 根拠 |
|---|---|---|---|
| 見出し | `=== feed-triage 実行サマリ (...) ===` | `=== feed-triage 実行サマリ [DRY-RUN] (...) ===` | F-005 AC-005 |
| 投入欄 | `投入 {n} 件`（実際に POST が成功した件数） | `投入対象 {n} 件 (投入は行っていません)` | F-005 AC-003。**同じ `ingested` フィールドを異なる意味で表示する** |
| 前回比・経過期間 | 出力する | **出力しない** | dry-run は `runs.jsonl` に追記しない（SPEC-002 フロー #8）。前回比を出すと、dry-run を挟むたびに「前回」の指す実行がずれ、運用者が誤読する |
| 記事明細 | 出力しない | 出力する（フロー #10） | F-005 AC-002 |

> **`ingested` を dry-run で「投入対象件数」として表示する根拠:** SPEC-004 §4 は
> 投入対象件数を「dry-run ではこれがサマリの投入欄になる」と定めている。
> **フィールドを分けず文言で区別する**のは、両者が排他だからである（dry-run では
> POST を行わないため投入成功件数は常に 0）。ただし**同じフィールドが実行モードで
> 意味を変える**ことは誤読の温床であり、文言で必ず区別する（`投入` と `投入対象`）。

## 7. 非機能仕様（この仕様固有）

| 観点 | 仕様 | 対応要件 |
|---|---|---|
| オブザーバビリティ | サマリを標準出力、処理経過を標準エラーへ出し、リダイレクトで分離できること | REQ-NF-007 / F-004 AC-005 |

> 既定90日保持される（F-004 §6）。**本仕様は追加の永続化を行わない。**
> ログの保持は実行基盤の設定であり、SPEC の管轄外である。

## 9. 画面仕様

UI は持たないが、**標準出力の書式そのものが運用者との唯一の接点**であるため、
出力例を正典として示す。

### 通常実行（正常系）

```
=== feed-triage 実行サマリ (2026-07-28T09:00:00Z) ===

取得 8 件 / 新規 8 件 / 評価 8 件 / 投入 3 件

情報源別:
  jane-street       5 件 (前回 4)
  netflix-techblog  3 件 (前回 3)
  snowflake-blog    0 件 (前回 0)
  uber-engineering  取得失敗 (HTTP 404)

スコア分布: 3:2 5:3 7:2 9:1
評価コスト: $0.021 (8 件)
前回実行から 1.0 週
```

> **概況の「取得」は `sources[].fetched` の合計である。** 独立した値として
> 受け取らない（本仕様は集計しないが、合計は情報源別の内訳と**必ず一致すべき値**
> であり、別々に受け取ると両者がずれた出力を検出できない）。

### dry-run

```
=== feed-triage 実行サマリ [DRY-RUN] (2026-07-28T09:00:00Z) ===

取得 8 件 / 新規 8 件 / 評価 8 件 / 投入対象 3 件 (投入は行っていません)

情報源別:
  jane-street       5 件
  netflix-techblog  3 件

スコア分布: 3:2 5:3 7:2 9:1
評価コスト: $0.021 (8 件)

判定結果:
  [投入] 9 https://blog.janestreet.com/a-tour-of-ocaml/  A tour of OCaml
  [投入] 7 https://netflixtechblog.com/scaling-x/  Scaling X
  [見送] 4 https://example.com/weekly-roundup/  Weekly roundup
  [失敗] - https://example.com/broken/
```

### 失敗系の行を含む実行

**失敗系6行の書式はこの例が正典である。** ラベル文字列そのものが AC-011a の
「区別できる形」の実体であり、文言が変わると区別が失われる。

```
=== feed-triage 実行サマリ (2026-07-28T09:00:00Z) ===

取得 42 件 / 新規 20 件 / 評価 8 件 / 投入 0 件
**投入対象 3 件がすべて失敗しました**

情報源別:
  jane-street  42 件 (前回 40)

スコア分布: 3:2 5:3
評価失敗 2 件
再評価打ち切り 1 件
投入失敗 3 件
  失敗理由: rate_limited: 2 server_error: 1
投入未試行 5 件
持ち越し 12 件
評価コスト: $0.021 (8 件)
前回実行から 1.0 週
```

### 異常が含まれる実行

```
=== feed-triage 実行サマリ (2026-07-28T09:00:00Z) ===

取得 0 件 / 新規 0 件 / 評価 0 件 / 投入 0 件

**全 13 情報源の取得に失敗しました**

情報源別:
  jane-street       取得失敗 (タイムアウト)
  netflix-techblog  取得失敗 (HTTP 503)
  ...

スコア分布: (評価に成功した記事がありません)
評価コスト: $0.000 (0 件)
前回実行から 2.4 週 **（定期実行が起動しなかった可能性があります）**

**記録の永続化に失敗しました: push が3回とも失敗しました。次回実行で重複投入が
発生しうるため、状態ブランチを確認してください**
```

**表示ルール:**

| ルール | 詳細 |
|---|---|
| 警告の強調 | `**` で囲む（Markdown 記法）。カラー出力は用いない → OQ-003 / TASK-011 |
| 情報源名の桁揃え | 左詰め・幅は定義中の最長名に合わせる。**切り詰めない**（→ §5） |
| 0 件の扱い | 概況・情報源別は 0 でも必ず出す。失敗系（評価失敗・再評価打ち切り・投入失敗・投入未試行・持ち越し）は 0 なら行を省く |
| 失敗系のラベル | `評価失敗` / `再評価打ち切り` / `投入失敗` / `投入未試行` / `持ち越し`。**この文字列が AC-011a の「区別できる形」の実体である**（→ §9 の失敗系の例） |
| 失敗理由の内訳 | `投入失敗` の直下に2スペース字下げで1行。`失敗理由: {code}: {n}` をコードの辞書順に半角スペース区切りで並べる |
| 未完了の標識 | 見出し行の末尾に ` （未完了）` を付す（dry-run 標識は見出しの内部、未完了は末尾） |
| 空行 | 見出し・概況・情報源別・指標・警告の各ブロック間に1行入れる |
| 数値の書式 | 件数は整数、コストは小数第3位、経過週は小数第1位 |

> **失敗系の 0 件を省略する理由:** 常時表示すると平常時のサマリが `評価失敗 0 件 /
> 投入失敗 0 件 / 持ち越し 0 件 / 未試行 0 件` で埋まり、**異常時に増える行が
> 目立たなくなる**。運用者は毎週これを流し読みするため、平常時は短いほどよい。
> 一方、概況（取得・新規・評価・投入）は 0 であること自体が異常の兆候であり、
> 省略すると「実行されなかった」との区別がつかないため必ず出す（F-004 AC-020 / AC-021）。

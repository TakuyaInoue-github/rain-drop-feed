## 1. 概要

処理済みエントリの状態を、追記専用の JSONL ファイル（`state.jsonl`）として読み書きする。
取得したエントリと既存の状態を突合して評価対象を選び、評価後に結果を追記し、
状態専用ブランチへ永続化する。

あわせて、**実行単位のサマリを `runs.jsonl` に追記する**。エントリ単位の状態からは
「実行されたが新着0件だった週」と「実行されなかった週」を区別できず、情報源ごとの
取得件数も復元できないため、実行の記録を別に持つ（→ F-004 AC-003a / AC-008、TASK-048）。

同一 URL の行が複数存在しうるため、現在の状態は **URL ごとに `evaluated_at` が最大の行**
として再構成する（[ADR-005](../04_decisions/ADR-005_state_file_format.md) OQ-001）。この処理を
**畳み込み**と呼ぶ（→ `00_glossary.md`）。

> **粒度についての注記（Rule S-1 / S-2）:** フロー定義表が15行の目安を超えるため分割を
> 検討したが、**統合を維持する**。#1〜16 は `StateRecord` 単一の状態機械（§6）に対する操作で
> あり、分割すると §6 の状態遷移表の置き場が決まらない（Rule S-2 が求める「独立した状態機械」に
> 該当しない）。#5 / #17〜21 の永続化群は別エンティティ（ブランチの HEAD）・別タイミング
> （実行末尾に1回）・別の再試行戦略を持ち Rule S-2 の分割トリガーに該当するが、分割後が5行と
> なり Rule S-3（3行以下は統合）に近く、かつ ADR-002 の決定1本で閉じるため本仕様に含める。

## 2. 前提条件 (Preconditions)

| 前提条件 | 満たされない場合の挙動 |
|---|---|
| 状態ブランチ `state` が存在すること | 初回実行とみなし、空の状態から開始する（→ フロー #10） |
| `state.jsonl` が存在すること | 空の状態（0件）として扱い処理を継続する（→ フロー #10） |
| 状態ブランチへの書き込み権限（`contents: write`）があること | 永続化の段階で失敗する（→ フロー #22）。取得・評価は完了しているため、その実行分の記録を失う |
| 既定ブランチと状態ブランチが分離されていること | 本仕様は状態ブランチのみを対象とする。既定ブランチへ書き込まないことは検証対象であり、前提ではない（→ F-002 AC-033 / T-031） |

## 3. フロー定義

> 本仕様は無人 CLI のバッチ処理であり、対話的な画面を持たない。
> 「ユーザーへの表示 / レスポンス」列は **標準出力・標準エラー出力への出力内容**、
> および呼び出し元（`pipeline`）への戻り値を指す。

| # | フロー種別 | 条件 / トリガー | アクター | 操作・イベント | システムの処理 | ユーザーへの表示 / レスポンス |
|---|---|---|---|---|---|---|
| 1 | 主系 | 実行開始時 | システム | 状態の読み込み | 状態ブランチを fetch し `state.jsonl` を1行ずつパースする | （標準エラー）`状態を読み込みました: {行数}行 / {URL数}件` |
| 2 | 主系 | 読み込み完了後 | システム | 現在状態の再構成 | URL ごとに `evaluated_at` が最大の行を採用し辞書を構築する | - |
| 3 | 主系 | 取得したエントリが存在する | システム | 評価対象の選定 | 未知の URL と、失敗回数が上限未満の URL を抽出する（新規を優先 → §6）。**同一 URL が複数含まれる場合（複数の情報源が同じ記事を配信した場合を含む）、最初の1件のみを対象とする** — 一意化は本仕様が担い、SPEC-001 は行わない（→ R-002） | （標準エラー）`評価対象: 新規 {n}件 / 再評価 {m}件` |
| 4 | 主系 | 各エントリの評価が完了 | システム | 結果の追記 | 評価結果を1行の JSON としてローカルの `state.jsonl` 末尾に追記する | - |
| 4a | 主系 | 全処理の完了時 | システム | 実行サマリの追記 | 当該実行の要約を1行の JSON として `runs.jsonl` 末尾に追記する（**評価対象が0件でも追記する**。実行された事実を残すため） | - |
| 5 | 主系 | 全エントリの処理完了 | システム | 永続化 | `state.jsonl` と `runs.jsonl` の変更をコミットし状態ブランチへ push する | （標準エラー）`状態を保存しました: {追記行数}行` |
| 6 | 代替系 | IF 評価対象が 0 件 | システム | - | `state.jsonl` への追記は行わないが、**`runs.jsonl` への追記と push は行う**（実行された事実を残さないと「実行されなかった週」と区別できないため → F-004 AC-008） | （標準エラー）`新規エントリがありません` |
| 7 | 代替系 | IF 評価対象が上限件数を超過 | システム | 評価対象の選定 | 新規を優先して上限まで選び、超過分は選定しない（記録もしない → 持ち越し）。**新規どうしはフィードからの取得順、再評価どうしは `evaluated_at` が古い順**に選ぶ（→ §6 の注記）。持ち越し件数はサマリに出力する（→ SPEC-006） | （標準エラー）`上限に達したため {n}件を次回に持ち越します` |
| 8 | 代替系 | WHERE dry-run が指定されている | 運用者 | 実行 | 状態の読み込みと突合は行うが、**`state.jsonl` / `runs.jsonl` への追記・コミット・push を一切行わない**（dry-run を前回実行として記録すると経過期間の判定が狂うため） | （標準出力）dry-run の判定結果（→ SPEC-006） |
| 9 | 代替系 | IF 同一 URL の行が複数存在する | システム | 現在状態の再構成 | `evaluated_at` が最大の行を採用する。**同値は発生しない**（→ §4 の精度規定）。行順には依存しない | - |
| 10 | 例外系 | IF 状態ブランチまたは `state.jsonl` が存在しない | システム | 状態の読み込み | 空の状態（0件）として処理を継続する。初回実行時に発生する | （標準エラー）`状態が見つかりません。初回実行として続行します` |
| 11 | 例外系 | IF `state.jsonl` に不正な行（JSON パース失敗）が含まれる | システム | 状態の読み込み | 当該行をスキップし、行番号を警告として記録して処理を継続する | （標準エラー）`状態の {n}行目を解釈できません。この行を無視します` |
| 12 | 例外系 | IF 行が JSON として妥当だが必須項目（`url` / `evaluated_at`）を欠く | システム | 状態の読み込み | 当該行をスキップし、警告として記録して処理を継続する | （標準エラー）`状態の {n}行目に必須項目がありません。この行を無視します` |
| 13 | 例外系 | IF `evaluated_at` が解釈できない日時形式 | システム | 状態の読み込み | 当該行をスキップする（順序判定に使えないため） | （標準エラー）`状態の {n}行目の評価日時を解釈できません。この行を無視します` |
| 14 | 例外系 | IF `url` が空文字または NULL | システム | 状態の読み込み | 当該行をスキップする（一意性のキーにできないため） | フロー #12 と同じ |
| 15 | 例外系 | IF 追記対象の URL が既に同一実行内で追記済み | システム | 結果の追記 | 追記しない（一意制約はアプリ側で担保する → [ADR-005](../04_decisions/ADR-005_state_file_format.md) のトレードオフ / TASK-051） | （標準エラー）`{url} は既に記録済みのためスキップします` |
| 16 | 例外系 | WHEN ローカルへの追記が失敗（書き込み不能・ディスク不足） | システム | 結果の追記 | 実行を失敗として終了する（終了コード 3） | （標準エラー）`状態の書き込みに失敗しました: {理由}` |
| 17 | 例外系 | WHEN push が競合により拒否される | システム | 永続化 | `pull --rebase` して行マージし、再 push する（最大3回） | （標準エラー）`他の実行と競合しました。統合して再試行します（{n}/3）` |
| 18 | 例外系 | IF rebase 中に競合が解決できない | システム | 永続化 | 両方の行を残す形で解決する（追記専用のため行順に意味がない） | （標準エラー）`競合を統合しました` |
| 19 | 例外系 | WHEN push の再試行が3回とも失敗 | システム | 永続化 | 実行を失敗として終了する（終了コード 3） | （標準エラー）`状態の保存に失敗しました。次回実行で重複投入が発生する可能性があります` |
| 20 | 例外系 | WHEN 状態ブランチへの書き込み権限がない | システム | 永続化 | 実行を失敗として終了する（終了コード 3）。リトライしない（権限は再試行で解決しない） | （標準エラー）`状態ブランチへの書き込み権限がありません` |
| 21 | 例外系 | WHILE リモートが応答しない（タイムアウト） | システム | 状態の読み込み / 永続化 | 読み込み時は記事を1件も投入せず失敗として終了する（終了コード 3 → F-002 AC-018）。永続化時はフロー #17 と同じリトライ | （標準エラー）`状態ブランチにアクセスできません: {理由}` |
| 22 | 例外系 | WHEN プロセスが強制終了される（SIGKILL 等） | システム | - | 未 push の記録を失う。**本仕様では対処しない**（→ ADR-002 の受け入れたトレードオフ） | 出力なし（プロセスが即座に終了するため） |

> **確認チェック:** 例外系9項目の検討結果
> - [x] **未認証アクセス** — フロー #20。状態ブランチへの書き込み権限がない場合
> - [x] **権限違反アクセス** — フロー #20 と同じ。本システムは認証機構を持たず、Git の権限に委ねる（REQ-NF-005）
> - [x] **必須項目未入力** — フロー #12 / #14。`url` / `evaluated_at` を欠く行
> - [x] **最大値・最小値超過** — フロー #7（評価件数の上限）。ファイルサイズの上限は ADR-005 の再検討条件で扱う
> - [x] **空文字・NULL入力** — フロー #14（`url` が空）。他項目は §4 の入力定義を参照
> - [x] **外部システムの障害** — フロー #21（リモートが応答しない）
> - [x] **タイムアウト** — フロー #21
> - [x] **同時操作・競合** — フロー #17 / #18（push 競合と rebase）
> - [x] **対象リソースが存在しない** — フロー #10（状態ブランチ / ファイルが存在しない）
> - [x] **対象リソースが削除済み** — フロー #10 と同じ扱い（全損時は初回実行と同様に振る舞う。評価記録の復旧は保証しない → F-003 AC-005）

## 4. 入出力定義

### 入力

`state.jsonl` の1行に対応するオブジェクト。**adapters 層のパース処理が**読み込み時に検証し、
欠落項目を下表の既定値で補完した上で `StateRecord` を構築する（`domain` 層は補完済みの
レコードのみを扱う）。

| 項目名 | 型 | 必須 | 制約 | NULL・空文字の扱い | 備考 |
|---|---|---|---|---|---|
| `url` | string | Yes | 一意性の判定キー | **行をスキップする**（フロー #14）。キーにできないため | 正規化は行わない（REQ-F-002 除外条件） |
| `title` | string | No | - | 空文字として扱い処理を継続する | 記録の可読性のために持つ |
| `source_name` | string | No | `feeds.yaml` の `name` と対応 | 空文字として扱う。情報源別の集計から漏れる | F-003 AC-004 が参照する |
| `evaluated_at` | string | Yes | ISO 8601 形式・UTC・**マイクロ秒精度**（同一実行内で同一 URL の複数行が同値にならないこと） | **行をスキップする**（フロー #13）。順序判定に使えないため | 畳み込みに用いる（ADR-005 OQ-001）。精度を規定するのは、同値時に行順へ依存すると rebase 後に非決定的になり、ADR-005 が排除した性質を持ち込むため |
| `score` | integer \| null | No | 0〜10 の整数 | `null` は「評価に失敗した」ことを意味する（有効な値） | 範囲外は読み込み時に `null` として扱う |
| `weight` | integer | No | - | 欠落時は 0 として扱う | 情報源の重み |
| `final_score` | integer \| null | No | `score + weight` | `score` が `null` なら `null` | 投入判定に用いた値 |
| `ingested` | boolean | No | - | 欠落時は `false` として扱う | 投入したか |
| `reason` | string | No | - | 空文字として扱う | 評価理由 |
| `suggested_tags` | array\<string\> | No | - | 欠落・`null` は空配列として扱う | 提案タグ |
| `failure_count` | integer | No | 0 以上 | 欠落時は 0 として扱う。負値は 0 に丸める | 総試行回数（週数ではない → F-001 AC-015） |

#### `runs.jsonl` の1行（実行単位の記録）

エントリ単位の状態からは復元できない情報を保持する（→ TASK-048 の結論）。
**dry-run では追記しない**（フロー #8）。

| 項目名 | 型 | 必須 | 制約 | NULL・空文字の扱い | 備考 |
|---|---|---|---|---|---|
| `run_at` | string | Yes | ISO 8601 形式・UTC・マイクロ秒精度 | 行をスキップする（順序判定に使えないため） | 実行の開始時刻。経過期間の算出に用いる（F-004 AC-008） |
| `sources` | object\<string, integer\> | Yes | 情報源名 → 取得件数 | 欠落・`null` は空オブジェクトとして扱う | **取得0件の情報源も含める**（前回比の算出に必要 → F-004 AC-003a / AC-022） |
| `source_errors` | object\<string, string\> | No | 情報源名 → 失敗理由 | 欠落は空オブジェクト | 取得に失敗した情報源（F-004 AC-010） |
| `new_entries` | integer | No | 0 以上 | 欠落時は 0 | 突合後の新規件数 |
| `evaluated` | integer | No | 0 以上 | 欠落時は 0 | 評価を試みた件数 |
| `ingested` | integer | No | 0 以上 | 欠落時は 0 | 投入に成功した件数 |
| `deferred` | integer | No | 0 以上 | 欠落時は 0 | 上限超過による持ち越し件数（F-004 AC-004a） |

> **注記:** 本ファイルは前回比の算出にのみ用いる。サマリに出力する項目の定義は
> SPEC-006 の管轄であり、本仕様は**保持すべき最小限**を定める。
> 行数は年52行程度で、`state.jsonl` に比べ無視できる規模。

### 出力

| 項目名 | 型 | 内容 | 条件 |
|---|---|---|---|
| 現在状態 | dict\<string, StateRecord\> | URL をキー、最新レコードを値とする辞書 | 常時 |
| 評価対象 URL | list\<string\> | 新規を優先した順序の URL 列 | 常時（0件でも空リストを返す） |
| 持ち越し件数 | integer | 上限超過により選定しなかった件数 | 上限を設定した場合 |
| 無視した行数 | integer | パース失敗・必須項目欠落によりスキップした行数 | 常時（0件を含む） |
| **直前の実行記録** | RunRecord \| null | `runs.jsonl` の `run_at` が最大の行。存在しなければ `null`（初回実行） | 常時。F-004 AC-003a / AC-008 の供給元 |

## 5. バリデーション仕様

| 項目 | ルール | タイミング | エラーメッセージ |
|---|---|---|---|
| 行全体 | JSON として解釈可能であること | 読み込み時 | `状態の {n}行目を解釈できません。この行を無視します` |
| `url` | 存在し、空文字でないこと | 読み込み時 | `状態の {n}行目に必須項目がありません。この行を無視します` |
| `evaluated_at` | 存在し、ISO 8601 として解釈可能であること | 読み込み時 | `状態の {n}行目の評価日時を解釈できません。この行を無視します` |
| `score` | `null` または 0〜10 の整数であること | 読み込み時 | 範囲外は `null` に丸め、警告のみ出力する（行はスキップしない） |
| `failure_count` | 0 以上の整数であること | 読み込み時 | 負値は 0 に丸め、警告を出力する（書き込み側のバグの兆候であり、黙って丸めると検知できないため） |
| `weight` | 整数であること。値域は制約しない（-1 / 0 / +1 を想定するが将来の拡張を妨げない） | 読み込み時 | 非整数は 0 に丸め、警告を出力する |
| `final_score` | `score + weight` と一致すること | 読み込み時 | 不一致なら `score + weight` で再計算した値を用い、警告を出力する: `状態の {n}行目の最終スコアが不整合です。再計算した値を用います` |
| 追記する URL | 同一実行内で未追記であること | 追記時 | `{url} は既に記録済みのためスキップします` |

> **注記:** 読み込み時の検証は**寛容な側**に倒す。1行の破損で全体を失うと
> R-002（重複ゼロ）に直結するため、スキップして継続する（フロー #11〜14）。
> 一方、書き込み時の失敗は実行を止める（フロー #16）。記録できないまま投入を続けると
> 重複投入が確定するため。

## 6. 状態遷移

処理済みエントリは以下の状態を持つ。状態は明示的なフィールドではなく、
`score` と `failure_count` の組み合わせから導出する。

### 状態一覧

| 状態 | 判定条件 | 説明 |
|---|---|---|
| 未知 | 状態に該当 URL の行が存在しない | 一度も評価していない |
| 評価失敗（継続中） | `score` が `null` かつ `failure_count < 上限` | 次回実行で再評価する |
| 評価失敗（打ち切り） | `score` が `null` かつ `failure_count >= 上限` | 以降再評価しない |
| 評価済み | `score` が `null` でない | 処理済み。投入の有無は `ingested` が示す |

### 遷移定義

| 現状態 | イベント | 次状態 | 条件 | 不可の場合の挙動 |
|---|---|---|---|---|
| 未知 | 評価に成功 | 評価済み | - | - |
| 未知 | 評価に失敗（意味的不正） | 評価失敗（継続中） | `failure_count` を試行回数分加算した結果が上限未満 | 上限以上なら「打ち切り」へ直接遷移する |
| 未知 | 評価に失敗（API 呼び出し自体） | **未知のまま** | - | `failure_count` を加算せず、行も追記しない（F-001 AC-015a） |
| 未知 | 上限件数超過により評価せず | **未知のまま** | - | 行を追記しない。次回に持ち越す（F-001 AC-025） |
| 評価失敗（継続中） | 再評価に成功 | 評価済み | - | - |
| 評価失敗（継続中） | 再評価に失敗（意味的不正） | 評価失敗（継続中） | 加算後の `failure_count` が上限未満 | 上限以上なら「打ち切り」へ |
| 評価失敗（継続中） | 再評価に失敗（API 呼び出し自体） | 評価失敗（継続中） | - | `failure_count` を加算しない。行も追記しない |
| 評価失敗（打ち切り） | （イベントなし） | - | - | 評価対象に選定されないため遷移しない |
| 評価済み | （イベントなし） | - | - | 同上。投入済みエントリの再スコアリングは行わない（F-001 Out of Scope） |

> **注記:** 追記専用のため「遷移」は物理的な上書きではなく、新しい行の追記により
> 表現される。旧状態の行も残るが、`evaluated_at` の比較により最新のみが有効になる。
>
> **選定順序の注記:** 評価件数の上限により再評価対象が部分的にしか選ばれない場合、
> **`evaluated_at` が古い順**（＝最後に試してから最も時間が経ったもの）を優先する。
> 選ばれなかった対象は次回実行でさらに古くなるため先頭へ近づき、**すべての再評価対象が
> いずれ必ず選ばれる**。取得順に依存させると、フィード末尾の記事が毎週漏れ続ける
> 飢餓が起こりうるため、この規則で構造的に防ぐ（F-001 AC-025a の裏返しの保証）。

## 7. 非機能仕様（この仕様固有）

| 観点 | 仕様 | 対応要件 |
|---|---|---|
| パフォーマンス | 全件をメモリに読み込み辞書に畳み込む。5年で最大 26,000行を想定し、この規模で実行時間目標を圧迫しないこと。**行数の上限は設けず、全件ロードを継続する**（20,000行到達時の扱いは OQ-003） | REQ-NF-001, ADR-005 |
| 整合性 | 一意制約は DB ではなくアプリケーション側で担保する。追記前に必ず現在状態の辞書と照合する | ADR-005 のトレードオフ, TASK-051 |
| **入力の一意化** | 取得されたエントリ列に同一 URL が複数含まれる場合、**評価対象として選ぶのは最初の1件のみ**とする（フロー #3）。SPEC-001 は取得段階で一意化せず（記録に残すため）、SPEC-004 も突合を行わない（「突合済みの集合を受け取る」）ため、**本仕様が唯一の一意化の担い手である**。ここが欠けると同一実行内で同じ記事が2回投入され R-002 に反する | R-002（Must）, SPEC-001 §5, SPEC-004 §7 |
| **完全性（追記のみ）** | 状態ファイルは**追記モードでのみ開き、切り詰め（truncate）・既存行の書き換え・削除を行わない**。定期実行ジョブは追記以外の操作を行わない | F-003 AC-031 / AC-032 |
| **事後検証可能性** | 全行に `url` / `title` / `source_name` / `score` / `reason` / `evaluated_at` / `ingested` を持たせ、畳み込み後の集合に対してスコア分布・任意閾値での投入対象件数・**個々の記事の特定**を可能にする。評価失敗行は `score` が `null` であることにより分布算出から除外できる | F-003 AC-006 / AC-006a / AC-010 / AC-013 |
| 耐障害性 | 読み込み時の部分的な破損は当該行のスキップで吸収する。書き込み失敗は実行を止める | REQ-NF-004 |
| データ保護 | 記録には公開記事のメタデータとスコアのみを含め、秘匿情報を書き込まない | REQ-NF-006, F-003 AC-030 |
| 可用性 | 状態の読み込みに失敗した場合、空の状態で続行してはならない（全件を新規とみなし重複投入を招くため） | F-002 AC-018, REQ-NF-004「状態を読めない場合の扱い」 |

> **実装参考: Git 操作の対応コマンド**
>
> 状態ブランチの操作は以下のコマンド相当を用いる（実装は adapters 層に隔離する。
> `subprocess` は常にリスト引数で呼び出し、`shell=True` を用いない → ADR-004 設計原則(4)）。
>
> ```
> 初回（状態ブランチが存在しない場合 → フロー #10）:
>   git switch --orphan state
>   git commit --allow-empty -m "chore(state): initialize state branch"
>   git push origin state
>
> 読み込み:
>   git fetch origin state
>   git show origin/state:state.jsonl
>
> 永続化:
>   git add state.jsonl runs.jsonl
>   git commit -m "chore(state): record {N} entries ({YYYY-MM-DD})"
>   git push origin HEAD:state
>
> 競合時:
>   git pull --rebase origin state   # 行マージ。両方の行を残す
>   git push origin HEAD:state       # 最大3回まで再試行
> ```
